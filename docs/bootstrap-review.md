## 持续集成另外发现的问题

1. `1121536` 修复 `compact_checks.cpp` 对临时共享指针内 vector 的悬空引用。Linux 曾在该测试中崩溃；修复是延长测试基底对象生命周期，未改变密码算法。失败运行 `39361886824`、`39361886837` 保留，修复后的标准回归 `39362418100` 通过全部 12 项。
2. `ac25f4f` 修复 Python argparse 的前缀缩写：`--k` 被误当成 `--key-trials`。k=2 被错误拒绝，k=3 可能实际按默认 k=2 执行。关闭前缀缩写，并测试两种参数顺序、k=2/3、slots64 与40层透传。`39362418373` 中的 bootstrap 部分不计入正式证据；其独立 compact 对照使用另一解析器，不受影响。
3. 修正参数解析后的 `39363025867` 原计划每个runner连续18次40层实验；根据已观察到的单次时间，90分钟预算可能截断。该批次取消并保留已完成和中断记录，不能标为完整通过。`6582e9d` 将调度改为12个同机对照片，每片6次，正式批次为 `39367123814`。算法源码、消息族、精度门槛及总72次样本不变；由独立合并检查逐项核对k/槽数/完整模数/40次乘法/8次刷新/全槽数/哈希/同机环境，再准入完整批次。

上述分片调度和合并脚本是最初两条源审查之后增加的交付工具。耗时变化使用每片同机比值的中位数，不把不同机器的绝对时间直接相除。
